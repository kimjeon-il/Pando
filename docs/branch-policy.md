# 브랜치 및 상설 워크트리 운영 정책

`kimjeon-il/Pando`가 웹 루트, `apps/web-shell/` 앱과 `shared/` 공통 코어를 보관하는 단일 저장소다. 웹과 앱은 같은 Git 커밋의 웹 UI·Worker·WASM을 사용하며 플랫폼 연결은 별도로 검증한다. 이전 `kimjeon-il/PandoEditor` 저장소는 복구용 원본으로 보존하며, 이 저장소의 새 작업은 그쪽으로 자동 동기화하지 않는다.

## 유지할 브랜치

| 브랜치 | 주요 책임 |
| --- | --- |
| `main` | 검증·승인된 통합본과 웹 Pages 게시 원본 |
| `work/ui` | 웹·앱 화면과 입력 |
| `work/objects` | 객체·관계·기간·저장 모델 |
| `work/gis` | GIS 자료·역사 경계·수계·지형·자료 조사 |
| `work/places` | 도시·지명 자료와 표시 |

기존 `work/*` 브랜치와 상설 워크트리를 재사용한다. 분야는 파일 경로별 소유권이 아니라 주된 작업 목적을 뜻한다. 작업별 브랜치·워크트리는 기본으로 만들지 않는다. 예외 브랜치나 임시 워크트리가 필요하면 이유와 종료 기준을 설명하고 사용자 승인을 받는다.

## 작업 전 확인과 동기화

1. `git worktree list --porcelain`로 해당 브랜치의 상설 워크트리를 찾는다. 그곳에서 `git status --short --branch`와 미추적 파일을 확인한다.
2. `git fetch origin` 후 로컬·원격 브랜치의 앞뒤 관계를 확인한다.
3. 작업 브랜치가 뒤처졌다면 미완성 작업을 보존하면서 `main → work/*` 방향으로 병합한다. 충돌을 임의로 한쪽만 선택해 해결하지 않는다.
4. 해당 워크트리에서 웹 루트와 `apps/web-shell/`·`shared/`의 변경을 함께 검토하고, 필요한 범위만 검사·커밋·푸시한다.

`work/* → main` 통합, `main` 직접 수정, Pages 배포는 사용자의 명시적 지시가 있을 때만 한다. 범주 사이에서 변경을 옮길 때에도 목적과 미완성 작업의 혼입 여부를 확인한다. 현재 통합 작업의 승인은 해당 작업 범위에 적용된다.

## 보존 원칙

- 작업 뒤에도 상설 워크트리와 브랜치를 유지한다. 자동 삭제·prune·캐시 정리를 하지 않는다.
- 관련 없는 미커밋·미추적 변경을 stash, reset, clean, 강제 checkout, 강제 push로 폐기하지 않는다. 파괴적 작업에는 사용자 승인이 필요하다.
- 공통 C++의 CMake 빌드는 각 워크트리의 별도 빌드 디렉터리를 사용한다. 다른 워크트리의 산출물을 덮어쓰지 않는다.
- 원본 앱 저장소와 이력 정리 전 미러는 복구 근거로 유지한다. 단일 저장소 전환 이후 원본 앱 저장소에 자동 push하지 않는다.

## 검증과 배포

웹 루트의 정적 파일만 `.github/workflows/web-pages.yml`로 Pages에 게시한다. `apps/`와 `shared/` 소스는 게시 대상에서 제외한다. 앱은 같은 커밋의 웹 산출물을 staging하며 플랫폼 연결은 별도 검사한다. 원본 데이터 핀, 과거 Web/App SHA, 별도 교환 검증은 역사적 근거로 남기며 현재 동등성이라고 표시하지 않는다.

`main` 반영 전에는 영향받은 웹·앱 검사와 Pages 게시 파일 검증을 수행한다. workflow 성공, 원격 push, 실제 사이트 응답은 각각 확인하고 기록한다. 전체 테스트나 포터블 패키지는 필요한 경우에만 실행하며, 포터블 앱은 사용자가 명시적으로 요청한 경우에만 만든다.

## 외부 자료 저장소

라이브러리 객체·런타임 지도·원자료·보고서는 `kimjeon-il/PandoLab-library-data`에 둔다. `config/library-data.json`이 각 코드 브랜치와 짝인 자료 커밋을 고정한다. `node tools/library-data.mjs`로 고정 캐시를 준비하며 `assets/data`와 조사 원자료 경로는 Git에서 제외된 마운트다. 보고서는 경로 helper가 제공하는 외부 원문 작업본에 작성하고 `node tools/library-data.mjs --store`로 자료 저장소 `reports/`에 보관한다. 자료 저장소는 보관용이며 검사·테스트·재생성을 실행하지 않는다.
