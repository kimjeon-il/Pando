# 브랜치 및 상설 워크트리 운영 정책

`kimjeon-il/Pando`가 웹 루트, `apps/web-shell/` 앱과 `shared/` 공통 코어를 보관하는 단일 저장소다. 웹과 앱은 같은 Git 커밋의 웹 UI·Worker·WASM을 사용하며 플랫폼 연결은 별도로 검증한다. 이전 `kimjeon-il/PandoEditor` 저장소는 복구용 원본으로 보존하며, 이 저장소의 새 작업은 그쪽으로 자동 동기화하지 않는다.

## 유지할 브랜치

| 브랜치 | 주요 책임 |
| --- | --- |
| `main` | 검증·승인된 통합본과 웹 Pages 게시 원본 |
| `work/ui` | 웹·앱 화면과 입력 |
| `work/objects` | 객체·관계·기간·저장 모델 |
| `work/gis` | GIS 자료·역사 경계·수계·지형·자료 조사 |
| `work/places` | 도시·지명 자료와 표시 |

기존 `work/*` 브랜치와 상설 워크트리, 워크트리별 고정 빌드 디렉터리를 재사용한다. 분야는 파일 경로별 소유권이 아니라 주된 작업 목적을 뜻한다. 작업마다 새 작업공간·저장소 복제본·브랜치·워크트리·빌드 폴더를 만들지 않는다. 필요한 상설 워크트리가 없고 기존의 적절한 작업공간에서 처리할 수 없을 때만 생성한다. 예외 브랜치나 임시 워크트리가 필요하면 기존 공간으로 처리할 수 없는 구체적인 이유와 종료 기준을 설명하고 사용자 승인을 받는다.

## 작업 전 확인과 동기화

1. `git worktree list --porcelain`로 해당 브랜치의 상설 워크트리를 찾는다. 그곳에서 `git status --short --branch`와 미추적 파일을 확인한다.
2. `git fetch origin` 후 로컬·원격 브랜치의 앞뒤 관계를 확인한다.
3. 작업 브랜치가 뒤처졌다면 미완성 작업을 보존하면서 `main → work/*` 방향으로 병합한다. 충돌을 임의로 한쪽만 선택해 해결하지 않는다.
4. 해당 워크트리에서 웹 루트와 `apps/web-shell/`·`shared/`의 변경을 함께 검토하고, 필요한 범위만 검사·커밋·푸시한다.

`work/* → main` 통합, `main` 직접 수정, Pages 배포는 사용자의 명시적 지시가 있을 때만 한다. 범주 사이에서 변경을 옮길 때에도 목적과 미완성 작업의 혼입 여부를 확인한다. 현재 통합 작업의 승인은 해당 작업 범위에 적용된다.

## 보존 원칙

- 작업 뒤에도 상설 워크트리와 브랜치를 유지한다. 삭제·prune에는 명시적 사용자 승인이 필요하며, 예외 브랜치나 임시 워크트리도 통합 후 자동 삭제하지 않는다.
- 관련 없는 미커밋·미추적 변경을 stash, reset, clean, 강제 checkout, 강제 push로 폐기하지 않는다. 소스·사용자 데이터·미완성 작업·원본 자료·증거를 폐기하는 작업에는 명시적 사용자 승인이 필요하다. 아래 조건을 충족하는 미사용·재생성 가능한 캐시와 생성물 정리에는 별도 승인이 필요하지 않다.
- 공통 C++의 CMake 빌드는 각 워크트리의 고정된 별도 빌드 디렉터리를 재사용한다. 다른 워크트리의 산출물을 덮어쓰지 않는다.
- 원본 앱 저장소와 이력 정리 전 미러는 복구 근거로 유지한다. 단일 저장소 전환 이후 원본 앱 저장소에 자동 push하지 않는다.

## 저장공간과 생성물 정리

저장공간 운영의 단일 규정은 [AGENTS.md의 Storage and generated-file cleanup](../AGENTS.md#storage-and-generated-file-cleanup-mandatory)이다. 모든 작업에서 해당 규정의 작업 전 용량 확인, 중복 생성 방지, 작업 종료 시 정리 및 실제 확보 용량 보고를 준수한다. 구체적인 사용처 없는 생성물을 막연히 보관하지 않는다.

## 검증과 배포

웹 루트의 정적 파일만 `.github/workflows/web-pages.yml`로 Pages에 게시한다. `apps/`와 `shared/` 소스는 게시 대상에서 제외한다. 앱은 같은 커밋의 웹 산출물을 staging하며 플랫폼 연결은 별도 검사한다. 원본 데이터 핀, 과거 Web/App SHA, 별도 교환 검증은 역사적 근거로 남기며 현재 동등성이라고 표시하지 않는다.

`main` 반영 전에는 영향받은 웹·앱 검사와 Pages 게시 파일 검증을 수행한다. workflow 성공, 원격 push, 실제 사이트 응답은 각각 확인하고 기록한다. 전체 테스트나 포터블 패키지는 필요한 경우에만 실행하며, 포터블 앱은 사용자가 명시적으로 요청한 경우에만 만든다.

## 외부 자료 저장소

라이브러리 객체·런타임 지도·원자료·보고서는 `kimjeon-il/PandoLab-library-data`에 둔다. `config/library-data.json`이 각 코드 브랜치와 짝인 자료 커밋을 고정한다. `node tools/library-data.mjs`로 고정 캐시를 준비하며 `assets/data`와 조사 원자료 경로는 Git에서 제외된 마운트다. 보고서는 공유 자료 저장소 루트 `reports/`의 원문을 두 언어의 경로 helper로 읽고, 쓰기는 `.edits/<브랜치>`의 독립 편집본에 한정한다. `.owners.json`의 브랜치별 revision과 `.variants/<sha256>`의 다른 판본을 보존하며, 자료 준비 때 보고서 전체를 작업트리에 복제하지 않는다. `node tools/library-data.mjs --store --include-prefix=reports/<범위>`로 지정한 변경만 보관하고 보고서만 저장하면 런타임 자료 핀을 바꾸지 않는다. 미복원 파일의 부재를 삭제로 해석하지 않는다. 보관 원문 삭제는 원문 작업 범위에서 파일을 명시적으로 보존·이동하거나 삭제한 뒤 `--remove-path=reports/<파일>`로 명시한다. 자료 저장소는 보관용이며 검사·테스트·재생성을 실행하지 않는다.

## 보고서 작업 완료

보고서·증거를 작성하거나 수정한 작업은 아래 완료 명령으로 원문 보관·라이브러리 main 커밋·푸시·원격 바이트 검증까지 끝낸다. 이 작업의 완료된 범위에 한해 별도 승인 없이 수행하며, 앱 main 통합·배포나 미완성 자료 공개의 승인을 뜻하지 않는다.

`node tools/library-data.mjs --publish-reports --include-prefix=reports/<scope>`

보고서만 있는 작업도 같은 기준을 적용한다. 최종 증거를 덧붙였으면 다시 실행하고, `--check-reports`로 재확인한 라이브러리 커밋과 범위를 완료 보고에 적는다. 기존 자료 핀·개인 작업 커밋·다른 작업의 편집본을 함께 공개하지 않는다. 잠금·충돌·푸시·원격 검증 실패는 미완료로 보고하며 원문과 대기 커밋을 보존한다. 자세한 사용법은 [외부 라이브러리 자료](library-data.md#보고서-완료-명령)를 따른다.

## 보고서 주제와 판본

새 보고서 경로는 아래 여섯 주제만 사용하며, Node/Python 경로 helper에
`reports/<주제>/<작업 범위>`를 직접 전달한다. 옛 분류나 경로 별칭을 만들지 않는다.

| 폴더 | 세부 분류 |
| --- | --- |
| `borders` | `history` 존속기간·역사, `reconstruction` 국가별 재구성, `validation` 검증, `data` 자료 |
| `hydro` | `names` 명칭, `calibration` 교정, `connectivity` 연결성, `releases` 버전 기록 |
| `places` | 도시·지명 조사 |
| `terrain` | 지형 조사 색인과 고정 원자료 링크 |
| `map-analysis` | `corpus` 학습 자료, `models` 모델, `reports` 평가·조사 |
| `development` | `ui`, `rendering`, `performance`, `ci`, `integrations`, `releases`, `storage`, `native` |

보고서와 스크린샷·로그·검증 JSON은 같은 작업 묶음에 둔다. 공용 첨부는
정본 한 곳에 보관하고 링크한다. 런타임·GIS 원자료 마운트는 유지한다.
보고서 revision은 런타임 pin과 독립적이며, 자료 준비·저장으로 되돌리지 않는다.
브랜치별 다른 판본은 `refs/pando/reports/<owner>`와 기존 편집본으로 보존한다.
완료된 범위만 보관·커밋·푸시·원격 검증하고 다른 작업의 편집본은 공개하지 않는다.
