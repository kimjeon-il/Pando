# Editable owner library and independent data delivery

Accepted conversation plan: Windows editor only; public Web remains a viewer. Edit existing entity/version identities, names/flags/lifetimes/sources/geometry, create/delete entities and dated versions, undo/redo, retain exact dates. Library edits must not mutate open projects or previously instantiated copies. Use existing C++ geometry commands and renderer. External files and GitHub data revisions must not depend on executable build hashes.

1. External library repository and native transport. Seed the existing packed catalog once into the user's AppData library. Native API reads the active external index/entities, atomically commits multi-entity changes using an expected revision, preserves history, and detects external edits. GitHub CLI authentication stays native. Private repository default kimjeon-il/PandoLab-library-data; sync on open/focus/save and periodically. Offline saves stay queued; conflicts preserve both sides; publishing is separate.
2. Canonical editable library service. Extend the existing catalog/service, retaining schema/date validation and entity identities. Draft/history has one owner, full-day precision, atomic neighboring-boundary edits via existing C++ operations, explicit version correction versus addition. No project temporal feature and no model migrations.
3. Native-only editing UI and isolated geometry editing. Existing library opens metadata/version controls and save/reload/sync/publish/conflict flows. Reuse an isolated instance of the existing editor for geometry changes; never swap or mutate the caller's project. Public viewer includes no edit UI or credentials.
4. Independent publication manifest and GitHub Actions tooling. Build and validate data from one immutable private source revision, publish immutable public release data and update Pages only after validation. Keep executable and source code unchanged per data edit. Existing current schemas only, offline last-verified revision explicit.
5. Focused regression tests, real browser and native checks, fresh final code review. Canonical report in reports/development/testing and index update. Preserve unrelated worktree changes.

Initial baseline: permanent work/ui FF from 955134d4 to origin/main 4f35c345. Preexisting 873 deleted tests, six generated permission modifications and 365 untracked generated artifacts preserved. Do not restore these deletions or copy another worktree's tests. New tests belong to this task only.

External setup and first live publish are a separate rollout after local implementation/validation, as agreed. Do not create remote repositories, push shared branches, merge main, configure secrets or publish without the rollout instruction.

Native contract (all errors reject with operation-specific code/message): library_open -> {revision,index,status}; library_read_entity({entityId}) -> normalized source JSON value; library_commit({expectedRevision,index,entities,deletedEntityIds}) -> open result; library_sync -> {state,revision,remoteRevision,conflict?}; library_publish({revision}) -> {state,sourceRevision,runUrl?}; library_conflict({choice:'local'|'remote'}) resolves explicit preserved conflict. library_open_geometry({entityId,versionId}) opens isolated editor; geometry transport will be coordinated separately. Native commands use app-data scoped storage and gh/git subprocesses with argument arrays, no shell/token exposure. Initial bundled gzip sources may be decoded by a small pinned native dependency; only one active external catalog after bootstrap.
