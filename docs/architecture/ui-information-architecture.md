# UI Information Architecture v2

이 문서는 `추가`와 `편집` Surface의 정보 위계를 고정한다. 4단계의 목적은 새 기능이 들어올 때 메뉴 분류와 편집 헤더가 다시 기능별 예외로 퍼지는 것을 막는 것이다.

## 추가 Surface

최상위는 객체 종류가 아니라 **획득 경로**다.

```text
추가
├ 만들기
│  ├ 영토·구역
│  │  ├ 국가
│  │  ├ 권역
│  │  ├ 행정구역
│  │  └ 지방
│  ├ 인문 분포
│  │  └ 분포 → 언어 / 민족 / 종교
│  └ 지형지물
│     ├ 지명
│     ├ 강
│     └ 호수
└ 라이브러리
```

`라이브러리`는 객체 유형이 아니라 프로젝트에 객체를 획득하는 경로다. 따라서 `자료` 같은 별도 객체 분류 아래로 이동하지 않는다. Generic Feature(`기타 객체`)는 데이터 손실 방지 fallback이므로 `만들기`에 노출하지 않는다.

`만들기`의 대분류 명칭과 순서는 레이어의 대분류와 동일한 `영토·구역 → 인문 분포 → 지형지물`을 사용한다. 향후 새 타입을 추가할 때도 획득 경로와 객체 분류를 섞지 않는다.

## 편집 Surface

P1 Shell 기준 편집 화면의 위계는 다음으로 고정한다.

```text
Surface Header: 모바일 sheet handle 등 shell chrome
ObjectContext:  국기 + 객체명 + 유형 + 상태 + 지도에서 보기 + 객체 메뉴
Object menu:     표시/숨김 + 잠금/잠금 해제
Tabs:            정보 / 편집 / 관계
Content:         선택 객체의 속성 또는 명령
Danger:          삭제
```

Surface Header는 편집 Surface 자체의 shell만 담당한다. 객체의 이름·유형·상태와 선택 객체 명령은 Surface Header로 올리지 않는다.

ObjectContext의 이름은 두 줄까지 허용하고 이후 말줄임한다. 유형과 잠금·숨김 상태는 보조 정보 줄에 표시한다. `지도에서 보기`는 빠른 위치 확인을 위해 헤더에 직접 유지하고, 표시/숨김과 잠금처럼 빈도가 낮은 보조 명령은 `객체 메뉴` overflow에 둔다. 영토 객체의 국기는 정체성 표시와 기존 국기 관리 진입점을 함께 유지한다.

P1에서는 기존 `정보 / 편집 / 관계` 탭과 실제 편집 기능을 변경하지 않는다. 삭제는 다른 보조 명령과 섞지 않고 편집 본문 맨 아래의 danger 영역에 둔다.

## 빈 선택과 다중 선택

선택이 없으면 ObjectContext 대신 선택 안내를 표시한다. 다중 선택도 별도 헤더를 만들지 않고 같은 편집 Surface와 ObjectContext 위계를 사용한다. 다중 선택의 세부 기능은 가능한 공통 속성과 공통 작업으로 제한한다.

## CI 계약

`scripts/check-ui-information-architecture.mjs`가 다음을 검사한다.

- `추가`의 `만들기 / 라이브러리` 경로 유지
- `만들기`의 대분류 명칭·순서와 주요 객체 타입
- Generic Feature 직접 생성 금지
- 편집 Surface Header는 shell chrome만 소유하고 객체별 정보는 침범하지 않음
- `header → ObjectContext → tabs → body` 위계 유지
- ObjectContext의 이름/유형/상태와 지도에서 보기/overflow 계약
- 표시/숨김과 잠금이 ObjectContext의 객체 메뉴에만 존재하는지
- 삭제가 최종 danger section에만 존재하는지
- 객체명 두 줄 표시 계약

UI 정보구조를 바꿀 필요가 생기면 검사 예외를 추가하기보다 이 문서의 제품 구조부터 갱신한 뒤 계약을 함께 수정한다.
