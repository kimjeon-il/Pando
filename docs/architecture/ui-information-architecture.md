# UI Information Architecture v2 — 편집 UI 설계 기록

> **적용 상태:** 이 문서의 `추가`·`편집` Surface, Windows 검수기 및 관련 버튼 구성은 이전 편집 제품의 정보구조 결정이다. 현행 Pando는 읽기 전용 Web Viewer이므로 이러한 편집 화면을 현행 필수 UI로 간주하지 않는다. 공통 글자·컨트롤·반응형 설계 정책은 [UI Architecture](ui-architecture.md), 제품 화면과 코드 소유권은 [현재 Viewer 모듈](../app-module-ownership.md)을 따른다. 당시 설계 및 UI 검증 의도는 아래에 보존한다.

이 문서는 2026년 당시 `추가`와 `편집` Surface의 정보 위계를 고정했다. 4단계의 목적은 새 기능이 들어올 때 메뉴 분류와 편집 헤더가 다시 기능별 예외로 퍼지는 것을 막는 것이다.

## 추가 Surface

최상위는 객체 종류가 아니라 **획득 경로**다.

```text
추가
├ 만들기
│  ├ 영토·구역
│  │  ├ 국가
│  │  ├ 권역
│  │  ├ 행정구역
│  │  └ 지방
│  ├ 인문 분포
│  │  └ 분포 → 언어 / 민족 / 종교
│  └ 지형지물
│     ├ 지명
│     ├ 강
│     └ 호수
└ 라이브러리
```

`라이브러리`는 객체 유형이 아니라 프로젝트에 객체를 획득하는 경로다. 따라서 `자료` 같은 별도 객체 분류 아래로 이동하지 않는다. Generic Feature(`기타 객체`)는 데이터 손실 방지 fallback이므로 `만들기`에 노출하지 않는다.

`만들기`의 대분류 명칭과 순서는 레이어의 대분류와 동일한 `영토·구역 → 인문 분포 → 지형지물`을 사용한다. 향후 새 타입을 추가할 때도 획득 경로와 객체 분류를 섞지 않는다.

## 편집 Surface

P1 Shell 기준 편집 화면의 위계는 다음으로 고정한다.

```text
Surface Header: 모바일 sheet handle 등 shell chrome
ObjectContext:  국기 + 객체명 + 유형 + 상태 + 지도에서 보기 + 객체 메뉴
Object menu:     표시/숨김 + 잠금/잠금 해제
Tabs:            정보 / 편집 / 관계
Content:         선택 객체의 속성 또는 명령
Danger:          삭제
```

Surface Header는 편집 Surface 자체의 shell만 담당한다. 객체의 이름·유형·상태와 선택 객체 명령은 Surface Header로 올리지 않는다.

ObjectContext의 이름은 두 줄까지 허용하고 이후 말줄임한다. 유형과 잠금·숨김 상태는 보조 정보 줄에 표시한다. `지도에서 보기`는 빠른 위치 확인을 위해 헤더에 직접 유지하고, 표시/숨김과 잠금처럼 빈도가 낮은 보조 명령은 `객체 메뉴` overflow에 둔다. 영토 객체의 국기는 정체성 표시와 기존 국기 관리 진입점을 함께 유지한다.

P2에서도 `정보 / 편집 / 관계` 구조와 기능 위치를 유지한다. 단순화는 새 disclosure·요약 행·그룹을 추가하는 방식이 아니라 기존 카드 chrome, 여백, 반복 설명을 줄이는 방식으로 수행한다. 영토 정보 탭은 이름·존속기간·색상·비고를 기본으로 노출하고, 명칭 상세는 기본 UI에서 노출하지 않는다. 삭제는 기존 편집 본문 맨 아래의 danger 영역을 유지한다.

## 빈 선택과 다중 선택

선택이 없으면 ObjectContext 대신 선택 안내를 표시한다. 다중 선택도 별도 헤더를 만들지 않고 같은 편집 Surface와 ObjectContext 위계를 사용한다. 다중 선택의 세부 기능은 가능한 공통 속성과 공통 작업으로 제한한다.

## CI 계약

현행 Viewer 검증은 [핵심 검증 정책](../policies/validation.md)을 따른다. 과거 Viewer·Windows 양쪽 정보구조 검증을 전제로 작성된 아래 확인 항목은 당시 검증 범위로 보존하며, 폐기된 Windows 제품을 다시 배포하지 않는다.

- 검수 패널 버튼과 요청 내보내기가 폼을 제출하지 않는지
- 검수 자료 다중 파일 선택과 읽기 전용 프로젝트 파일 선택을 유지하는지
- 검증 전 검수 요약·목록·상세·비교 영역이 숨겨져 있는지
- 검수 콘텐츠의 표시 순서, 독립 사이드바와 모바일 메뉴 접근성 이름을 유지하는지

UI 정보구조를 바꿀 필요가 생기면 검사 예외를 추가하기보다 이 문서의 제품 구조부터 갱신한 뒤 계약을 함께 수정한다.
