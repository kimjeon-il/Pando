# P5-5 공유 국경선 렌더링 패킷 성능 검증

- 범위: 국가 간 접촉 후보 탐색·공유 경계 결과 조립을 이전 P5 단계에서 통합한 이후, 마지막 렌더링 패킷 계산을 C++/WASM으로 통합한 결과
- 기준: `b436f85`의 기존 JS 패킷 조립기. 동일한 C++ 경계 선분 연결·세분화 프리미티브를 사용하므로 이번에 제거한 JS 조립 계산의 비용을 비교한다.
- 대상: `work/objects` 커밋 `9cf08caa` (최초 수치), 이후 성능 회귀 CI 지속 측정
- 실행: GitHub Actions Ubuntu 24.04, 저장소 고정 Node 버전, JS/WASM 소스 해시 검증, `--expose-gc`
- 측정: 같은 프로세스·동일 소스 입력에서 워밍업 뒤 반복 호출 중앙값. 최초 측정은 기존 JS와 C++ 각 3회(정밀)/5회(기타)의 순차 실행, 이후에는 순서 교대 측정 적용

| 입력 | 원본 공유 선분 | 기존 JS 중앙값 | C++/WASM 중앙값 | 단축률 |
| --- | ---: | ---: | ---: | ---: |
| 실제 미리보기 | 12,729 | 267.298 ms | 214.619 ms | 19.7% |
| 실제 정밀 | 68,616 | 1,405.970 ms | 1,134.492 ms | 19.3% |
| 합성 고부하 | 8,192 | 166.091 ms | 133.503 ms | 19.6% |

### 정확성 검증
실제 캐시(미리보기·정밀) 및 합성 입력 모두에서 출력 선분 좌표, 소유국 집합, 연속 범위, 점선 위상, GPU 스트로크 메타데이터가 구 구현과 일치하였다. 변형 없는 원본 지도 캐시 v1을 사용했으며 캐시 본문은 재생성하지 않았다.

### 한계와 판정
- 표의 시간은 공유 국경선 **렌더링 패킷 생성 단계**의 시간이지 전체 지도 프레임 렌더링 시간이나 앱 시작 시간이 아니다.
- 초기 측정의 GC 할당량 중앙값은 미리보기 JS 70.729 MiB/C++ 34.617 MiB, 정밀 JS 180.115 MiB/C++ 124.696 MiB였다. 합성 입력에서 경향이 반대이므로 GC·WASM 할당기 영향을 배제할 수 없다. **메모리 개선율로 확정하지 않는다.**
- 실제 지도 캐시 기준 약 19~20%의 처리시간 감소를 확인했다. 전체 앱·웹 결과 검증은 P3 브라우저와 Linux·Windows Qt CI를 별도로 확인한다.
- 후속 CI 성능 게이트: 동일 러너의 이전 JS 대비 미리보기·정밀 1.15배 초과 느려지는 경우, 합성 입력은 1.25배 초과 느려지는 경우 실패 처리한다. 절대 시간은 하드웨어와 부하에 따라 달라질 수 있어 게이트로 사용하지 않는다.
