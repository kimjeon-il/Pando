## 대상과 수정

사용자가 승인한 초기 표시 시차·새 프로젝트 흰 화면 해결책을 구현했다. 기존 영토·지형 자료, 프로젝트 형식과 시간 기능은 바꾸지 않았다.

- 프로젝트 교체 중 기존 렌더 조정자가 지도와 지명 갱신을 함께 보류한다. 기존 GPU 장면 캐시를 읽기 전용으로 다시 표시하고, 창 크기가 바뀌어도 이전 CSS 좌표를 유지한다. 보존 화면은 새 프로젝트의 준비 완료나 선택 자료로 인정하지 않는다. 새 세대 메시 준비가 끝나면 기존 갱신 경로로 전환한다.
- 최초 열기에서 전역 육지 바탕과 지형 준비를 프로젝트 읽기와 겹친다. 국가 메시가 없어도 육지 바탕이 준비되면 같은 base pass에서 바다와 육지를 표시한다. 이 화면은 정밀 경계 준비 완료가 아니다.
- 물리 지도 바다·수계의 자동 색을 기존 테마 소유자로 통합했다. DEM 색상 준비 전에는 완성된 단색 바탕을 유지하고, 임시 회색 색상 텍스처가 바다·육지 표시를 갈라놓지 않게 했다. 정치 지도 색 의미는 유지한다.
- 수계는 Core에 객체 식별자를 등록하므로 조기 전역 배경 로딩에서 제외했다. 프로젝트 교체가 완료된 뒤 기존 로딩 경로에서 시작한다. 검토 중 실제 프로젝트 도메인으로 재현된 `PL-CORE-STALE` 교차 세대 등록 오류를 피한다.
- 읽기 모델이 전체 프로젝트를 복사한 뒤 형상 저장소에서 좌표를 다시 복사하던 중복을 제거했다. 형상 저장소의 검증·복사·동결과 속성의 분리 복사는 유지한다. 배열을 동결할 때 임시 `Object.values()` 배열도 만들지 않는다. 전체 생성 시간이 몇 초 줄었다는 측정 주장은 하지 않는다.

별도 프로젝트 상태나 로딩 상태, 새 렌더러 서비스는 만들지 않았다. 보존된 장면은 기존 캐시의 명시적 전환 표시로만 사용한다.

웹 첫 흐름은 내장 지도 생성의 Core 응답을 의도적으로 지연시켜 이전 채움이 유지되는지 화면 픽셀로 확인한다. 창 너비 1440→1280 변경 중에도 지도는 남고, 완료 뒤 내장 객체가 있으며, 빈 지도 생성 뒤 모델과 화면에서 이전 객체가 사라진다. 페이지 오류는 0개다.

두 번째 흐름은 최초 내장 프로젝트 읽기와 모든 WebP 응답을 함께 보류한다. 정밀 국가 메시 전에도 바탕이 실제로 그려지고 유색 픽셀이 존재한다. 이때 `canonicalMeshReady=false`, 준비 상태는 `boundaries`, 열기 완료는 `false`다. 수계 manifest는 교체 전 요청하지 않고, 보류 해제 후 정상 열기 완료와 함께 요청한다. 페이지 오류는 0개다. 이는 모든 요소를 동시에 다운로드한다는 검사가 아니다.

Windows 앱 검사는 별도 WebView 프로필과 CDP를 사용했다. 내장 지도 생성 대기·창 크기 변경 중 지도가 유지됐고, 빈 지도 완료 후 객체 0개·유색 지도 픽셀 0개, 페이지 오류 0개였다. `native-result.json`에 적용 모듈 해시와 결과, `native-new-pending.png`에 대기 화면을 기록했다. 앱에서는 지형 기능이 꺼져 있으므로 웹 DEM 표시를 앱에서도 검증했다고 주장하지 않는다. WebView 프로필 분리와 네이티브 파일 저장소 분리는 동일하지 않으며, 자동저장·복구는 검증 범위가 아니다.

## 기존 미완성 변경과 테스트 처리

작업 시작부터 있던 테스트 삭제 874건, 자동 생성 권한 파일 수정과 미추적 자료를 보존했다. 삭제된 관련 테스트를 작업 디렉터리에 복원하지 않고, 기준 커밋의 테스트에 현재 필수 의존성 mock을 반영한 후보로 검사했다. 현재 계약을 사용하는 테스트 수정은 이번 커밋에 포함하되 기존 작업 디렉터리의 삭제는 유지한다.

읽기 모델의 기존 테스트 한 건은 변경 전 main에서도 실패했다. 현재 계약상 `presentation`에 속하는 `physicalSettings`를 `header`로 보내던 fixture를 현재 위치로 옮겼고, 잘못된 header 입력의 거부 검사도 유지·보강했다. 새 제품 동작에 맞추기 위해 검증을 느슨하게 하지 않았다. 기존 GPU pass mock과 DEM 색상 대기 브라우저 probe도 현재 pass 계약으로 갱신했다. 후자의 기존 브라우저 파일 전체와 `gpu-prepared-draw` 전체는 이번 최소 실행 범위에 넣지 않았다.

## 미실행 범위와 게시 상태

전체 테스트·C++ CI·전체 앱 빌드는 실행하지 않았다. WebGL1·Canvas, 강제 컨텍스트 손실, DPR 변경, 생성 실패/복구·Undo·저장 재열기, Android와 모바일 실기기, 실제 사용자 사용성 검증은 이번에 재검증하지 않았다. 위 미실행 항목을 통과로 표시하지 않는다.

수정은 `work/ui`에만 있다. main 반영·원격 push·Pages 배포·앱 실행 파일 갱신은 하지 않았다. 선행 보고서의 원인 조사와 대조 실험 기록을 보존하며, 구현·검증 상태는 이 후속 보고서를 따른다.
