## 대상과 방법

증상은 고배율에서 상세 지형으로 **늦게 전환되는 것**이다. 저화질에 영구 고정되는 별도 경로와 구분했다. Windows Chromium/D3D11에서 1440×900 CSS px, DPR 1로 처음 확대(S≈4800), 축소, 재확대, 작은 드래그를 반복했다. fetch·응답 body·이미지 디코딩·texImage2D 제출·renderer 준비 판정을 별도로 기록했다.

배포본에서 지연을 측정한 뒤 수정본을 로컬 서버에서 같은 실제 CDN과 함께 측정했다. 별도 결정적 브라우저 회귀에서는 같은 DEM 형식과 크기의 통제된 타일을 제공해 네트워크 속도를 제거하고, 포인터를 누른 상태에서 실제 프레임 준비까지 진행되는지 검사했다. 실제 사용자 사용성 평가와 네이티브 WebView App 실행 검증은 수행하지 않았다.

## 확인한 원인과 수정

1. 공유 GPU 스케줄러가 포인터/지도 조작 중 업로드 전체를 멈추고 종료 후 500ms를 추가 대기했다. 이미 다운로드·디코딩된 현재 화면 지형도 같은 대기에 묶였다. 기존 스케줄러에서 visible 작업만 조작 중 진행하도록 확장했다. 입력 이벤트 대기·숨긴 창·세대 취소는 계속 차단하며 프레임당 시간·바이트 예산을 공유한다. 배경 작업의 quiet 대기는 유지한다. 원자적인 텍스처 업로드 하나가 예산보다 큰 경우에는 해당 프레임의 나머지 작업을 중단한다.
2. 상세 음영은 배율 대신 조작 단계와 성능 등급에 연결되어 있었다. 조작 시 매번 저비용 음영으로 바꾸고 멈춘 뒤 180ms 혼합 전환했다. 이 전환 상태·타이머·기존 uniform/진단 필드를 제거했다. 기존 배율 판정으로 저배율은 사전 계산 음영, 고배율은 상세 음영을 선택한다. 고배율 드래그/성능 등급 변화가 상세 음영을 끄지 않는다.
3. 가시 타일 업로드가 끝나기 전에 이웃 타일을 미리 받고 모두 캐시 보존 대상으로 삼았다. 표시용 디코딩 대기와 캐시 압력을 키웠다. 현재 화면·바탕·필수 색채가 GPU에 준비된 뒤 남는 캐시 용량에서만 이웃 요청을 시작한다. 디코딩된 현재 화면 자료도 업로드 순서에서 우선한다. 새 화면으로 이동하면 미리 받던 요청 슬롯을 해제한다. 캐시 예산 자체를 무제한 늘리거나 전체 세계의 상세 지형을 미리 받지 않는다.
4. 평면지도의 작은 확대/이동은 이전 화면 이미지를 재투영할 수 있는데, 이때 지형 준비도 함께 건너뛰었다. 요청과 배율/타일 판정은 매 프레임 기존 지형 소유자에서 먼저 수행하고, 결과가 달라지면 화면 캐시를 무효화하도록 수정했다. 국가 메시가 이미 canonical이어도 저배율→고배율의 지형 음영 전환은 독립적으로 캐시를 갱신한다. 재투영 자체를 전면 폐기하거나 조작 종료 타이머에 다시 의존하지 않는다. 독립 검토에서 이 경로를 확인했다.

기존 `terrain-zoom-continuity` 검사는 교체를 최대 120초 기다리는 eventual 검증이며, 전환 속도 통과 근거가 아니었다. 새 검사는 입력을 해제하지 않은 상태에서 완료해야 한다. 수정 전 단위 회귀 4건과 브라우저 회귀 2건의 실패를 확인한 뒤 구현했다.

평면 재투영은 다른 자원의 무효화가 우연히 재그리기를 일으키면 브라우저 검사만으로 누락을 놓칠 수 있었다. 따라서 준비가 캐시 분기보다 먼저 실행되어야 한다는 소유권 순서 검사도 RED→GREEN으로 확인했다. 실제 브라우저에서는 평면 620→650의 상세 음영 draw와 DPR 1의 3000→3200에서 LOD 4→5 전환을 추가 확인했다. 정적 순서 검사를 실제 픽셀/전환 시간 측정처럼 보고하지 않는다.

이 표는 실제 CDN을 사용한 한 쌍의 관측이며 네트워크 조건이 완전히 같지 않다. 보편적인 성능 보장이나 실제 화면 표시 지연 전체의 수치로 해석하지 않는다. texImage2D 제출 시각은 GPU 실행 완료/화면 합성 시각과 다르다. 처음 방문한 상세 영역의 다운로드 대기는 남는다. 최초 확대의 마지막 업로드 제출은 2.67초→1.78초였지만 네트워크 개선율로 주장하지 않는다. 원시 JSON의 phase 경계 사이에서 준비 상태 표본이 생략될 수 있어 그 표본으로 전체 완료 시간을 추정하지 않았다.

- 단위/공유 업로드/지형 소유자: **44/44 통과**, 수정된 공유 스케줄러 계약의 별도 검사 **1/1 통과**. 실패 재시도, 오래된 응답, 컨텍스트 손실, 세대 취소, 기존 형상 유지, 캐시 해제도 포함한다.
- 통제된 실제 브라우저: **4/4 통과**. WebGL1·2 픽셀 검증과 데스크톱 1440px / 모바일 레이아웃 390px·DPR 2의 포인터 유지 중 상세 프레임 완료, 데스크톱 평면 지도의 작은 확대를 검사했다. 모바일 실기기/터치 성능을 입증한 것은 아니다.
- 기존 DEM 픽셀 회귀: **12/12 통과**. 높이 바이트 carry, 곡면 기울기, 위도 보정, gutter·공유 타일 모서리, 색채·테마·저배율 음영을 유지했다.
- 변경 JS와 직접 영향받은 검사에 ESLint 및 diff whitespace 검사를 수행했다.

검사 정합성 확인 중 `renderer-responsiveness-source`의 distribution/vertex 두 source-text 단언은 변경 전 main에서도 실패함을 재현했다. 이번 지형 회귀와 분리했으며 전체 검사가 통과했다고 보고하지 않는다. C++/WASM CI 문제는 이번에 실행하거나 수정하지 않았다.

## 반영 범위와 미검증

공유 업로드 스케줄러, 지형 준비 소유자, 기존 렌더러와 DEM 셰이더를 수정했다. 저장 형식·원본 GIS 자료는 변경하지 않았다. main 반영·원격 push·Pages 게시·앱 실행 파일 갱신은 이 검증에 포함되지 않는다. Canvas 직접 표시의 미리보기 고정과 full-world 자료 선택 정책은 이번 WebGL 전환 지연의 원인으로 단정하지 않았고 변경하지 않았다.

`work/ui`에는 별도 작업의 기존 테스트 874개 삭제와 네이티브 권한/미추적 산출물이 있다. 해당 삭제를 되돌리지 않고 원래 HEAD의 직접 영향받은 검사만 임시 실행본에서 새 계약에 맞춰 검증했다. 해당 검사 수정은 Git 인덱스의 현재 파일 버전에만 기록해 삭제 WIP를 보존한다. 새 회귀검사는 별도 파일로 남긴다. 원격 work/ui의 별도 두 커밋은 미완료 작업과 함께 보존하며 이 작업에서 자동 통합하지 않는다.
