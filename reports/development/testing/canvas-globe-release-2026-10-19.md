## 대상과 방법

Edge의 실제 Canvas Worker를 강제하여 1280×800 CSS px 창, 지도 1280×752, 홍콩 중심 지구본 배율 16에서 측정했다. WebGL을 비활성화한 별도 소유 브라우저를 사용했으며 사용자의 열린 브라우저 상태는 변경하지 않았다. Worker 계측은 테스트 응답에만 주입하고 제품에는 디버그 API를 추가하지 않았다.

초기 빈 프레임, 원본 형상 투영, 수계 최초 준비, 상세 지형 도착, 준비된 화면의 색상 토글을 구분했다. 단계 시간은 Worker 그리기 CPU 구간이다. UI 클릭 후 관측 시간에는 Playwright 동작·poll 대기 등이 포함되므로 이를 순수 입력 지연이나 FPS로 해석하지 않는다. 회귀 검사는 Worker가 보낸 자료뿐 아니라 실제 홍콩 육지 픽셀, 마지막 표시 스타일 revision과 변경 없는 프로젝트 상태를 확인한다.

## 확인된 원인과 수정

1. 지구본은 반구 clipping만 적용하고 화면 범위 clipping이 없어 확대된 화면 밖 육지까지 Canvas 경로에 제출했다. 기존 투영 생성기에 화면 extent를 추가했다. 지구 뒷면 제외 규칙은 유지한다. 별도 검토에서 화면 밖 선 중심의 굵은 stroke가 잘리는 문제를 찾아, 실제 선/점 반경과 Canvas miter·cap·수계 폭을 반영한 padding을 더했다. 폭 4px/40px 가장자리 회귀 사례를 red→green으로 확인했다.
2. 같은 육지를 바탕·지형 마스크·채색 단계마다 D3로 다시 투영했다. Worker가 현재 투영 하나의 정확한 D3 명령을 Float64 버퍼로 보관하고 재사용한다. 투영 인자, 프로젝트 세대, 형상 revision이 바뀌면 폐기한다. 형상 객체 교체도 별도 경로를 만든다. 스타일·색상은 캐시된 형상을 변경하지 않는다.
3. 고유 색상 토글에도 지형 타일 전체를 다시 그렸다. 기존 substrate의 소유권은 유지하고 카메라·DPR·육지 형상·지형 모드·테마와 실제 그릴 타일 조합이 같으면 재사용한다. 화면 밖 이웃 타일 prefetch는 재그리기를 일으키지 않으며, 화면에 필요한 상세 타일 도착은 기존 지형 계획에서 판정하여 갱신한다. 수요/LOD 규칙을 복제하지 않고 기존 계산을 `terrainRenderPlan`으로 분리했다.
4. 강은 선분마다 임시 geometry를 새로 만들고 호수 경계는 매번 다시 계산했다. 실제 형상 소유자 아래에서 동일 선분·경계와 투영 결과를 재사용한다. 선분별 폭·수계색·투명도·경계 단계는 유지한다. 초기 구현의 선분별 D3 path 생성은 첫 수계 준비에 약 13초를 쓰는 회귀를 일으켜 폐기하고, 한 paint의 모든 선분이 동일 D3 stream을 사용하도록 수정·회귀 검증했다.

새 지도 모델·색상 상속·경계 정책을 추가하지 않았고 원본 GIS·DEM·프로젝트 형식을 변경하지 않았다. 앞서 완료했던 이동 종료 표시 대상 갱신, 스타일 변경의 전 세계 형상 재전송 제거, 화면 밖 지형 삼각형 제외와 메뉴 상단 두 내장 항목 제거도 이번 게시에 포함한다.

## 측정과 검증

상세 DEM이 준비된 중간 구현은 색채 고유 색상 토글 프레임에 약 2.27~2.35초를 썼다. 이 중 지형 약 1.53~1.60초, 강 약 0.52초였다. 최종 색채 토글은 106.4~160.2ms, 흑백은 104.9~138.1ms였다. 최초 상세 준비 중 프레임 최대는 색채 2,136ms, 흑백 1,553ms로, 이 비용을 제거했다고 보고하지 않는다. 상세 수치는 [계측 근거](canvas-globe-release-2026-10-19.evidence.json)에 기록한다. 이전 보고서의 11.25초 프레임은 별도 탐색 측정이며 모든 수치가 동일 초기 상태의 A/B 비교라는 뜻은 아니다.

- 실제 DEM이 준비된 홍콩 육지의 색채 모드: 고유 색상 OFF `[124,170,150,255]`, ON `[142,144,128,255]`.
- 흑백 모드: OFF `[209,209,209,255]`, ON `[206,102,102,255]`. 흑백 바탕 209는 상속 빨강 R=204보다 크므로 ON에서 R이 항상 증가한다는 첫 테스트 가정은 잘못이었다. 제품을 바꾸지 않고 기존 alpha 합성식의 결과와 비교하도록 검사했다.
- 두 모드에서 OFF/ON을 두 차례 반복하여 지형 substrate 재사용, 750ms 미만 Worker 토글 프레임, 표시 revision 일치, 형상 재전송 없음, 프로젝트 내용·변경 상태 보존을 검사한다.
- 단위 검사는 화면 교차·반구 clipping, 구멍·섬·Point·Sphere의 D3 결과 일치, 카메라/형상 교체와 타일 도착 무효화, 하위 객체 마스크·색상 분리, 화면 밖 prefetch, 수계 폭·색·stream 재사용과 기존 Worker stale frame/완료 식별 계약을 포함한다.
- Web/App 소스 분리 및 누락 Worker/WASM 검사는 17개 통과, Windows symlink 권한 항목 1개 미실행이다. App small-project/full-world staging 단위 검사 7개 통과.
- 최종 관련 단위 검사 97/97 및 변경 JS/테스트 ESLint 통과. 브라우저 11개 묶음에서 10개가 통과했으며 viewer Canvas 경계 사례 1개는 메뉴/검색 클릭 안정성 대기에서 실패했다. 이 묶음을 11/11로 보고하지 않는다. 이 테스트는 Canvas에도 WebGL용 SwiftShader 실행 인자를 적용하고 있어 렌더러별 실행을 분리한 최종 재검사에서 viewer/editor Canvas 두 사례가 모두 통과했다(4개 묶음: 지형 두 모드 + 경계 두 제품, 4/4). 별도 앱 임시 보기·저장 분리 흐름 1개와 WebGL 경계·상속 사례도 앞선 묶음에서 통과했다. 전체 테스트 스위트는 실행하지 않는다.

## 한계와 배포

차가운 화면의 형상·상세 지형 최초 준비는 여전히 0ms가 아니며 네트워크 다운로드 시간을 없앤 작업이 아니다. 최종 냉간 프레임 시간은 별도로 기록한다. 브라우저 App 편집 진입점과 네이티브 Windows/Android 실행은 다른 검증이다. Windows CI에서 MSVC 재빌드와 실제 Tauri WebView 실행의 12개 startup 검사가 통과했다. 이는 WebGL2 기본 실행 증거이며 네이티브 강제 Canvas·전체 편집 회귀·로컬 수동 실행·Android 실기기 조작은 미검증이다.

제품 수정 `740e6669`, 빌드 `da7b7449`를 커밋·push하고, P2가 검증·기록한 생성본 `e401fa2980dad6662a915e4c9779206adcc2f0db`까지 main에 fast-forward 통합·push했다. 관련 없는 네이티브 권한 파일·portability fixture·미추적 결과 폴더는 보존하며 릴리스에 넣지 않는다. 독립 코드 검토의 가장자리 stroke 지적은 수정 후 4px/40px 회귀 사례 통과로 종결했다. 후속 결과는 이 절에 추가한다.


## 게시 확인

- [Pages 39247753519](https://github.com/kimjeon-il/Pando/actions/runs/39247753519)의 build/deploy가 source `e401fa29`에서 성공했다. 공개 buildId는 `0.36.0-build-da7b744937ec`, dataRevision은 기존 `data-88f083713d023870fafaa2d0eb1a3636`이다.
- 로컬 full staging `da7b7449`에서 1,315개 / 108,675,424 bytes를 검증했다. 후속 P2 생성본의 공개 파일 목록은 같고 index/build-meta 2개만 바뀌었다. 변경 없는 1,313개 검증 결과를 재사용하고 2개는 커밋 원문에서 다시 계산·포장했다. 전체 staging을 두 번 새로 실행했다고 주장하지 않는다. CI가 실제 게시한 1,315개 모든 파일의 path/blob/bytes/SHA-256이 이 최종 목록과 일치했다. 편집 앱 소스 104개와 공통 C++ 소스 173개는 게시되지 않았다.
- 변경된 모든 공개 파일과 공통 Worker 보조 파일을 포함한 19개 URL에서 HTTP 200과 커밋 SHA-256 일치를 확인했다. 공개 사이트의 원본 응답을 수정하지 않은 Edge에서 Canvas Worker·상세 DEM, 홍콩 OFF/ON 육지 픽셀, 표시 revision 일치, 형상 교체 0회, 문서 보존, runtime 오류 없음, 상단 내장 두 항목 부재를 확인하고 화면을 저장했다.
- 앱 full-world 실제 staging은 최종 생성본 기준 1,530개 / 148,243,933 bytes이며 포장된 Worker가 공통 소스와 일치한다. [Windows 실제 앱 CI](https://github.com/kimjeon-il/Pando/actions/runs/39247299264)는 생성 식별값 갱신 전 동일 제품 소스 `da7b7449`에서 12개 항목이 통과했다.
- [P1 관련 검사](https://github.com/kimjeon-il/Pando/actions/runs/39247299357), [P3 웹 검사](https://github.com/kimjeon-il/Pando/actions/runs/39247299309), [P2 생성 검증](https://github.com/kimjeon-il/Pando/actions/runs/39247299423)이 통과했다. 전체 저장소의 모든 CI가 통과했다는 주장은 아니다.
- 이 게시 근거를 추가하는 후속 문서 커밋은 게시 자산을 변경하지 않는다. 미커밋 권한 파일·fixture·로컬 결과 폴더는 그대로 보존한다.
