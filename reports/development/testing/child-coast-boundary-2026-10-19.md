# 하위 객체의 해안 점선 잔존 수정

> 보고서 ID: `UI-CHILD-COAST-20261019` · 상태: `focused-verified / unpublished / native-unverified` · 지도 반영: `not-applicable` · 색인일: 2026-10-19

> 조사 기준: 웹·앱 `f48aa4028a3e5165efafc086e3aa0da03ff5e1d0` 및 `work/ui` 미커밋 수정본
> 원본·출처: 사용자 공개 사이트 화면, 현행 CHN/HKG/MAC 원본 자료, 공통 경계 생성기와 실제 GPKG 열기 경로

## 대상과 기준

홍콩 하위 객체의 해안·섬에 흰 점선이 남는 현상을 조사했다. 역사 형상 복원이나 사료 정확도 조사가 아니라 현행 형상을 사용하는 표시 규칙 수정이다. 원본 GIS·프로젝트 형상·계층 관계·저장 형식은 변경하지 않는다.

## 근거와 원인

`buildTerritorialInternalBoundarySegments`는 부모의 원본 폴리곤과 겹치는 구간을 제외한 뒤 자식의 나머지 둘레를 내부 경계로 취급했다. 부모의 직접 소유 형상과 자식의 형상이 서로 인접하는 자료에서는 부모·자식 육상 접경을 제거하고, 부모 원본에 포함되지 않은 자식 해안을 점선으로 남기는 역전이 발생했다.

현행 CHN/HKG 원본을 직접 넣으면 하위 점선 380개 중 홍콩 남쪽(양 끝 위도 22.3도 미만)에 146개가 생성됐다. 합성한 인접 자식·떨어진 섬과 실제 원본 회귀 검사를 먼저 추가해 두 검사가 실패함을 확인했다.

[이전 웹·앱 경계 재점검](shared-map-rule-parity-2026-10-19.md)은 양쪽의 동일 입력·동일 출력을 비교했지만, 부모가 자식 영토를 포함하는 합성 도형을 사용했다. 양쪽이 같은 잘못된 공통 결과를 내는 이 자료 형태는 검증하지 못했다. 이전의 공유 확인을 경계 판정의 완전한 정확도 검증으로 해석하면 안 된다.

## 수정

기존 공통 경계 생성기에서 부모와 해당 계층의 일반 자식 형상을 공통 C++ 다각형 커널로 합쳐 외곽선 제외 형상을 파생한다. 전체 육지 외곽선을 제외하므로 바다에 면한 자식·섬은 사라지고 부모와 맞닿은 육상 접경은 남는다. 독립 권역은 합집합에 포함하지 않는다. 원본 형상은 불변이며, 기존 Worker의 형상·관계별 캐시를 사용한다. 카메라·스타일 변경마다 합집합을 다시 계산하는 경로를 추가하지 않는다.

## 검증과 한계

- 관련 단위 검사 62/62 통과: 실제 원본, 인접·겹친 자식, 떨어진 섬, 권역, 서로 다른 부모, 원본 불변, 캐시 재사용, 숨김, 실패·취소·응답 역전 처리.
- 수정 후 원본 홍콩은 육상 접경 14개만 남고 남쪽 해안 146개는 0개가 된다. 남는 선의 총길이는 별도의 기존 국가 공유 접경 계산 결과와 일치한다.
- 현행 MAC 원본과 CHN 사이에는 기존 공유 접경 계산에서도 일치하는 원본 선분이 없다. 원본에 없는 접경을 표시 코드에서 만들어내지 않았다. 마카오 자료의 접합 정확도는 별도 데이터 문제로 미검증이다.
- 변경한 JS·검사의 ESLint 통과. 웹·앱 편집 시작점 × WebGL/Canvas 브라우저 검사 4/4 통과(1440×900). 실제 메뉴·파일 선택기로 원본 3개 객체를 담은 현재 GPKG를 열고, 공통 장면에 들어가는 경계 좌표·길이에서 해안 제외와 육상 접경 보존을 확인했다. 평면 전환·검색·이동·확대까지 실행했으며 확대 화면 PNG는 `test-results-child-coast-final/`에 보존했다. 화면의 파란 선택 외곽선은 일반 하위 객체의 흰 점선과 구분한다.
- 최초 앱 검사에서는 지연 연결되는 파일 처리기를 활성화하지 않고 숨은 input에 파일을 주입해 열기를 시작하지 못했다. 기존 실제 메뉴·파일 선택 흐름으로 검사 준비를 고쳐 최종 네 가지 조합을 재실행했다. 제품 코드를 이 테스트 오류에 맞춰 변경하지 않았다.
- Windows·Android 네이티브 실행, 공개 사이트 재배포, 독립 역사 기준선의 0.5 CSS px 검사는 수행하지 않았다.
