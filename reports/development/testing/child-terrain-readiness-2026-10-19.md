# 하위 객체의 지형 표시 누락·지연 조사와 수정

> 보고서 ID: `UI-CHILD-TERRAIN-20261019` · 상태: `focused-verified / canvas-frame-bottleneck-remains / unpublished / native-unverified` · 지도 반영: `not-applicable` · 색인일: 2026-10-19
> 원문 최종 수정: 2026-10-19
> 조사 기준: 웹·앱 `f48aa4028a3e5165efafc086e3aa0da03ff5e1d0` 및 `work/ui` 미커밋 수정본
> 원본·출처: 사용자의 홍콩 흑백·색채 지형 화면, 고유 색상 해제와 지연 후 표시 관찰, 공통 렌더 조정기·Canvas 전송·실제 내장 지도

## 확인된 원인

기본색 상속 계산 자체는 정상이다. 실제 내장 홍콩은 CHN의 `#cc3333`을 상속하며 흑백에서 alpha 0.68, 색채에서 0.22로 전달됐다. 고유 색상을 끄면 색·alpha는 비지만 육지 소유·지형 마스크는 남아야 한다. 원본 색상·형상·관계·프로젝트 저장 형식은 변경하지 않았다.

1. 이동 종료 시 표시 대상 재계산 누락: 화면 밖으로 걸러 둔 하위 객체가 이동 후 화면에 들어와도 `VIEW_SETTLE`에는 라벨·HUD 갱신만 있었다. 실제 Canvas 브라우저에서 홍콩을 제외한 화면을 준비한 뒤 홍콩으로 이동하고 종료해도 하위 육지 packet이 없음을 재현했다. 다른 스타일 변경·비동기 준비 완료가 나중에 갱신을 일으키면 나타날 수 있는 경로다. 단위 검사에서도 이동 종료 후 `territorialUnits` 등의 호출이 0회였다.
2. 표시 변경을 형상 교체로 취급: `builtinTerritorialScene`이 표시 설정 변경으로 새 Feature 배열을 만들면 Canvas는 배열 참조 차이만 보고 전 세계 형상을 `replace-data`로 재전송하고 경계를 다시 준비했다. 브라우저 회귀 검사에서 형상 변경 없는 고유 색상 토글 한 번으로 교체 횟수가 3→4로 증가함을 확인했다. 초기 탐색 한 실행에는 교체 메시지 8개와 전체 Canvas 전송 추정량 약 183MB가 관찰됐다. 이는 계측 메시지 추정치이며 순수 형상 바이트나 다운로드 크기로 해석하지 않는다.
3. Canvas 지구본의 불필요한 화면 밖 이미지 복사: 지형 타일을 삼각형으로 그릴 때, 완전히 화면 밖인 삼각형도 clip·변환·이미지 복사를 실행했다. 실제 Worker 함수를 실행하는 단위 검사에서 화면 밖 삼각형 3개가 이미지 복사 3회를 일으켰다.

## 수정과 소유자

- 공통 `map-render-coordinator.js`의 이동 종료 마스크에 `OVERLAY_GEOMETRY`를 추가했다. 이동 중에는 기존 준비 자료를 재사용하고 종료 시에만 현재 표시 대상을 한 번 계산한다. 별도 모바일·웹·앱 목록이나 지도 모델은 추가하지 않았다.
- 기존 Canvas 전송 경계에서 프로젝트 세대, 렌더 ID 순서·구성, `geometryRevisionKey`, 경계 소유·원본 여부로 자료 식별값을 파생한다. 마지막으로 전송한 자료 식별값은 기존 전송 함수가 관리한다. 색상·투명도·새 Feature wrapper만 바뀌면 기존 style 메시지를 사용한다. 새 형상 객체·제자리 형상 수정·객체 추가/삭제·새 프로젝트는 교체 대상으로 남는다. 기존 배열 참조 판정은 제거했다.
- 기존 Canvas 지형 삼각형 함수에서 화면 밖의 이미지 복사를 보수적으로 제외한다. 화면을 가로지르는 삼각형과 기존 0.75 물리 px 겹침은 유지한다. 지형 자료를 단순화하거나 원본을 수정하지 않았다.

## 검증

- 공통 조정기·입력·GPU 장면·상속 관련 단위 검사 61/61 통과.
- Canvas 자료 식별·전송 수명·형상 revision·지형 독립성 관련 검사 26/26 통과.
- 화면 밖 삼각형·DEM 변환·가장자리·전송 관련 검사 27/27 통과. 위 두 묶음은 일부 중복이다.
- 이전 지형 독립성 fixture는 현행 `canvas-terrain-dem-core.js`를 로드하지 않고 projection의 `center()` getter도 구현하지 않았다. 변경 전 HEAD Worker로도 같은 실패를 확인했다. 실제 공통 helper와 현행 getter 계약을 fixture에 연결한 뒤 기존 지형 범위·표시/숨김·편집 형상·진행 로딩 기대값을 유지해 통과했다.
- 웹 브라우저 최종 회귀 검사 4/4 통과: 실제 내장 지도, 흑백·색채 시작 × WebGL2·Canvas Worker, Edge 1280×800. 실제 드래그로 하위 객체를 화면 안에 넣고 실제 고유 색상 메뉴를 끄고 켰다. 하위 육지 packet 유지, 상속 색·alpha, Canvas 색상 토글에서 전체 형상 재전송 0회, 문서 불변을 확인했다. Canvas 2개는 25.1초, 강제 SwiftShader WebGL2 2개는 2.2분이 걸렸다. 이는 전체 테스트 실행 시간이며 제품 로딩 시간이나 개선률이 아니다. 영수증은 `test-results-child-terrain-canvas-final/`, `test-results-child-terrain-webgl-final/`에 보존했다. packet 검사를 상세 지형 타일의 최종 화면·전체 로딩 시간 검증으로 취급하지 않는다.
- 앱 편집 시작점 브라우저 검사 1/1 통과: `editor-focus-storage.spec.mjs`의 temporary viewing 흐름. 보기 상태의 문서·저장 분리, 자료 지연 로딩, 앱 지형 요청 없음과 런타임 오류 없음을 재확인했다. 결과는 `test-results-child-terrain-editor-final/`에 보존했다. Windows 네이티브 앱 실행 증거는 아니다.
- 변경 JS·검사의 ESLint와 추적 파일 `git diff --check` 통과.

## 탐색 결과와 남은 한계

탐색 중 WebGL의 준비 완료 프레임에서는 홍콩의 흑백 채색 `[206,102,102,255]`, 색상 해제 시 회색 지형 `[198,198,198,255]` 등을 읽었다. Canvas에서도 준비된 흑백 화면의 채색·회색 픽셀은 확인했다. 처음 누락된 upload 프레임을 완성 프레임으로 취급한 검사와 라벨 halo가 섞이는 합성 화면 샘플은 최종 검증으로 집계하지 않았다. 탐색용 Worker 계측의 CRLF 치환 오류도 제품 결함으로 집계하지 않았다.

**색채 Canvas 지구본의 전체 지연이 해소됐다는 증거는 아직 없다.** 강제 Canvas, Edge, 1280×800의 탐색에서는 색채 지형 준비 중 한 프레임의 Worker 처리 시간 약 11.25초와 중립 바탕 위의 채색 픽셀이 관찰됐다. 그 프레임의 지형 삼각형 호출은 0개였다. 따라서 화면 밖 삼각형 제외만으로 그 긴 프레임이 해결됐다고 주장하지 않는다. 국가·수계 등 나머지 프레임 처리와 상세 지형 준비 비용의 분리 계측, 최종 색채 타일 표시와 cold/warm 총 로딩 시간은 추가 검증 대상이다. 단일 지점의 초록색 우세를 기대한 탐색 검사는 상세 타일 준비 전의 바탕 표시와 구분하지 못하므로 정식 회귀 검사로 채택하지 않았다.

원시 탐색 출력은 `test-results-terrain-*`, 수정 전 실패는 `test-results-terrain-inheritance-culling-red/`, `test-results-canvas-geometry-resend-red/` 등에 보존했다. 최종 회귀 검사는 source packet·실제 입력·전송 계약에 범위를 명시한다. 미완성 픽셀 탐색을 통과한 검사로 바꾸거나 상세 지형 검증으로 표시하지 않는다.

## 배포·네이티브와 판본

커밋·push·`main` 통합·Pages 배포·Windows/Android 네이티브 재빌드 및 실행은 수행하지 않았다. 기존 미커밋 메뉴·하위 해안 경계 수정과 다른 작업은 보존했다. [내장 메뉴 구분 제거 보고서](source-visibility-menu-2026-10-19.md)의 당시 비재현 기록을 대체하는 후속 조사이며, 당시 배포·검증 범위를 소급해 수정하지 않는다.
