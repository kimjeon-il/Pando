## 성능과 미검증 범위

최초 Node 계산 어댑터 비교에서 폴리곤·수계·참조이미지 회귀를 확인했다. WASM 좌표 일괄 전달, 수계 공간 인덱스 조회, 참조이미지 준비 계수/메시 배열 전달을 수정했다. 수정 후 성능 수용 판정은 P9에서 실시한다. 초기 수치를 해결된 문제처럼 기록하지 않는다.

이 Node 도구는 브라우저 프레임·Qt 화면·실기기를 측정하지 않는다. 최종 후보의 사용자 흐름, 원격 반복 측정, 실제 GPU·Windows 화면·Android 터치 검증은 아직 완료되지 않았다. 실기기가 없으면 해당 항목을 미검증으로 남기며 전체 P9 완료로 표시하지 않는다.

### WASM 예외 처리 비용 확인

- 38767156038 WASM 빌드 성공, 결과 69ec57c0. 폴리곤·참조·수계 관련 24개 검사 통과.
- 참조 경로의 짧은 CPU 측정에서 보정/준비 62%, C++ 메시/전달 17%, JS 조립 16%, 점 투영 5%였다. WASM→JS 및 invoke_* 프레임이 46 self samples 중 최소 8개였다. 짧은 계측 표본이며 전체 회귀의 원인 비율로 확정하지 않는다.
- 기존 CMake는 JS 예외 에뮬레이션(-fexceptions, DISABLE_EXCEPTION_CATCHING=0)을 전체 C++에 적용했다. - 계산 규칙을 더 바꾸기 전에 코어와 바인딩 모두 native WASM 예외 처리로 전환한다. 컴파일·링크에 같은 모드를 쓰고 JS 에뮬레이션 옵션을 제거한다. 네이티브 Qt 빌드에는 영향이 없다. 성능·현재 오류 계약·브라우저 실행은 새 산출물에서 확인하며, 미지원 WASM 엔진이나 실기기 통과를 가정하지 않는다.

## 요청된 접촉·메시 수정과 응답성 후속

- 최신 배포 WASM에서 날짜변경선 직사각형과 Greenwich 직사각형의 접촉을 재현했다. 실제로 Greenwich에 공유 선분 1개가 생성됐으며, 역방향/360° 이동 및 분할 회귀검사 3개가 수정 전 실패했다. 공통 C++에서 경도 연결·주기적 경계 상자·점 투영을 통일하고, 웹/앱 준비 인덱스가 같은 계산을 사용하도록 연결한다. 실제 날짜변경선 공유 경계와 원본 참조·입력 보존도 검사한다.
- Web과 Qt의 채움 삼각분할·구면 내부 변 세분화를 `shared/core`의 단일 구현으로 옮겼다. Web은 WASM, Qt는 직접 호출하며, 플랫폼별 출력 포장만 유지한다. 알고리즘 리비전 5 생성물은 기존 P2 그래프에서 원격 재생성한다. 이 시점에는 새 바이너리 검증 전이다.
- Qt 입력 준비 실패의 구체적인 원인은 preview CMG의 실제 source coordinate count **105,880**과 native decoder의 과거 고정 값 **105,884** 불일치였다. CMG 형식·소유권·배열 범위 검사는 유지하고 preview GeoJSON의 실제 좌표 합계 및 canonical manifest의 현재 값으로 교차 검증하도록 바꿨다. 기존 입력 9개의 SHA-256이 모두 유효한 상태에서 코드가 과거 통계를 강제한 오류였다.
- 상대 Qt 측정은 양쪽 모두 같은 전체 세계 저장 프로젝트를 열고 고정 국가 배경 메시를 비활성화한다. 기준본 제품 소스를 수정하지 않고 동일한 현재 프로젝트로 동적 메시 경로를 비교하기 위한 명시적 측정 범위이며, cold-world bootstrap 비교와 구분한다. 기존 측정 overlay 2개는 양쪽에서 동일하다.
- 브라우저 측정은 완료한 각 warmup/교대 쌍을 즉시 저장하고 진행 로그를 출력한다. 러시아 그룹의 정확한 저장 내용 검증은 비교 시간 밖에서 오래 걸리므로 계획된 5쌍과 한 차례 추가 회차가 끝날 수 있는 유한한 45분 실행 한도를 사용한다. 검증 기준·표본 수·추가 회차 횟수는 완화하지 않는다. 실제 측정 완료 전 성능 수용을 주장하지 않는다.
