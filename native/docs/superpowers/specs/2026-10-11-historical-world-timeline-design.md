# 기본 세계 지도와 역사 타임라인 연결 설계

작성일: 2026-10-11. 적용 대상: Pando 웹 및 PandoEditor 앱.

상태: 2026-10-11 사용자 문서 검토 승인. 이 사양을 기준으로 구현 계획을 작성한다.

## 1. 목적과 사용자 결정

새 기본 세계 프로젝트에서 날짜를 이동하면, 해당 시점에 유효한 역사 자료로 국가 경계와 소속 관계를 표시한다. 현대 경계를 모든 연도에 그대로 표시하는 문제를 해결한다. 웹과 앱은 같은 자료와 시간 의미를 사용하며 각 플랫폼의 기존 모델·편집·저장·렌더링 책임을 유지한다.

사용자가 확정한 범위:

- 우크라이나만 연결하지 않고 현재 역사 라이브러리의 전체 자료를 연결한다.
- 선택한 시점에 유효한 경계 자료가 없는 국가는 숨긴다. 현대 경계나 가장 가까운 연도의 경계로 채우지 않는다.
- 장기적으로 역사 자료를 채워 나간다. 이번 작업은 기존 자료 연결이며 새로운 역사 자료 조사는 포함하지 않는다.
- 보존해야 할 기존 프로젝트가 없다. 기존 프로젝트를 소급 수정하는 마이그레이션은 만들지 않는다.
- 웹과 앱을 함께 수정한다.

## 2. 확인한 원인과 자료 상태

배포 웹 `0.36.0-build-a5641da22713`에서 기본 세계를 만들 때 `createStaticTerritorialSnapshot`이 현대 국가의 수명·형상·부모 관계를 모두 무기한 기록으로 생성한다. 커서 이동은 이 프로젝트 기록만 해석하므로, 별도로 존재하는 역사 라이브러리의 날짜별 경계가 기본 지도에 반영되지 않는다.

실제 배포 모듈과 자료로 확인한 결과:

- `2012-10`에서도 현대 우크라이나와 러시아의 형상이 그대로 남고, 크림반도 내부 확인점 `[34.1, 44.95]`은 러시아에 포함된다.
- 라이브러리의 `state:ukraine:1991-2014-r1`은 같은 시점에 유효하며 이 확인점을 포함한다.
- 카탈로그에는 현대 스냅샷의 258개 참조와 추가 역사 객체 26개가 있다. 258개 참조는 기존 병합·하위 영토 분류 전의 수이며 독립 국가 수가 아니다.
- 조사한 인덱스 SHA-256은 `701f196f755c31a5c285f5cc7d5a1a477b1caa74059d502ba16e055080535751`이다.

현 자료로 월말에 표시 가능한 역사 경계의 예:

| 커서/자료 | 확인한 범위 또는 제약 |
| --- | --- |
| `2012-10` | 우크라이나와 나고르노카라바흐만 유효한 역사 경계가 있다. 나머지는 숨긴다. |
| `2015-10` | 나고르노카라바흐만 유효하다. 우크라이나나 러시아의 현대 경계로 채우지 않는다. |
| 우크라이나 | `1991-08-24`부터 `2014-03-17`까지. `2014-02`에는 표시하고 `2014-03` 월말에는 표시하지 않는다. |
| 소련 구성 공화국 15개 | 경계 자료는 `1991-01-01`부터 `1991-12-25`까지. 더 긴 객체 수명을 경계의 유효기간으로 간주하지 않는다. |
| 소련 | 원본 종료가 연도 정밀도 `1991`이므로 1991년 말까지라는 기존 시간 의미를 유지한다. 임의의 정확한 종료일을 넣지 않는다. |
| 유고슬라비아 | `1941-04-17` 이후부터 `1945-11-29` 이전까지 경계 공백이 있다. |
| 동독 / 북슐레스비히 | 각각 `1989-04-25` / `1900-01-01` 하루의 경계만 있다. 해당 월말까지 기간을 늘리지 않는다. |
| 현대 스냅샷 | `referenceDate: 2026-10-06`. 현재 형상을 과거 전체에 적용할 근거가 없다. |

자료의 낮은 확실성·근사 경계 표시는 유지한다. 이번 연결을 통해 역사 정확도를 높였다고 간주하지 않는다. 위 결과는 조사한 자료 리비전의 결과이며 자료 갱신 시 검증 기대값도 근거와 함께 갱신한다.

## 3. 시간과 존재 규칙

기존 `docs/timeline-contract.md`와 `docs/timeline-records.md`를 따른다.

1. 커서 `YYYY-MM`은 해당 달의 마지막 날이다. 시작과 종료는 양끝 포함이다.
2. 원본의 year/month/date 정밀도를 읽고 정확한 날짜 경계에서 구간을 계산한다. 월 단위로 원본 기간을 늘리거나 반올림하지 않는다.
3. 기본 프로젝트에서 객체가 존재하는 구간은 원본 수명, 유효한 형상, 유효한 부모 관계와 부모의 존재 구간이 모두 겹치는 구간이다. 서로 떨어진 구간은 복수 수명 기록으로 표현한다.
4. 유효 형상이 없거나, 부모 자료가 없거나, 영토 조정 후 형상이 비면 그 구간의 객체를 생성하지 않는다. 전 구간에 유효한 형상이 없으면 기본 프로젝트에서 그 객체를 제외하고 자료 보고서에 이유를 남긴다. 월말에 걸리지 않는 하루 기록도 원본 구간 그대로 보존한다.
5. 살아 있는 객체에는 형상과 부모 기록이 항상 존재해야 한다. 각 기록은 객체 수명 밖에 존재할 수 없다. 기존 전체 날짜 구간 검증을 통과해야 한다.
6. 형상에 `datePrecision: current`와 무기한 날짜가 있어도 이를 역사적 무기한 형상으로 취급하지 않는다. 현대 스냅샷은 원본 기준일이 속한 한 달에만 기본 지도의 자료로 제공한다. 현재 자료에서는 `2026-10`이다. 이는 월 단위 제공 정책이며 일 단위 역사 자료가 확보됐다는 뜻이 아니다.
7. 일반 역사 자료의 명시적 무기한 경계는 기존 계약대로 해석한다. 위 제한은 날짜 범위가 확인되지 않은 현대 스냅샷에 적용한다.
8. 원본 수명·형상 기간·기준일·정밀도·출처·확실성은 provenance에 보존한다. 파생 구간은 원본과 구별한다.

수명은 역사적 국가 존재 여부를 새로 판정하는 값이 아니라, 이 기본 프로젝트에서 자료를 갖추어 표시할 수 있는 구간이다. 자료 공백은 영토가 역사적으로 존재하지 않았다는 주장으로 해석하지 않는다.

## 4. 객체 정체성, 분류와 영토 중첩

### 객체 정체성

- 같은 라이브러리 객체의 형상 버전이 바뀌어도 논리 ID는 유지한다. 커서 이동 때 새 UUID를 생성하지 않는다.
- 현대 자료는 기존 기본 세계의 객체 ID·병합·하위 영토 분류를 유지한다. 원본 feature ID와 프로젝트 ID의 변환은 명시적으로 기록한다.
- 추가 역사 객체는 라이브러리 entity ID를 기준으로 결정적인 프로젝트 ID를 갖는다. 현대 객체와 별개인 역사 객체는 별개의 ID로 남긴다.
- 계보는 검색·분류 관계이며 동일 객체라는 근거가 아니다. 남북한, 동서독, 동·서프로이센 등을 계보 이름만으로 하나로 합치지 않는다.
- 이름·국기·색상·메모 및 기타 지원되는 속성은 기존 라이브러리/기본 세계 재료화 규칙을 따른다. 같은 객체의 시간별 표시 속성은 기존 기록 모델에서 지원하는 범위만 사용한다.

### 영토 중첩

부모와 하위 영토의 중첩은 기존 계층 모델의 의미로 허용한다. 서로 다른 루트 또는 같은 부모의 동급 영토 사이의 양의 면적 중첩은 다음과 같이 처리한다. 공유 경계선은 면적 중첩이 아니다.

1. 소련과 독립 우크라이나, 소련과 나고르노카라바흐의 중첩에는 명시적인 영토 대체 규칙을 둔다. 두 독립 역사 객체의 원본 유효 구간 동안 해당 형상을 소련에서 뺀다. 이 규칙은 선언된 객체와 기간에만 적용한다.
2. 소련의 하위 영토는 조정된 부모 형상에 맞춰 자른다. 독립 우크라이나가 차지한 구간에서 우크라이나 SSR의 형상이 모두 없어지면 해당 SSR을 숨긴다. 부모·자식 자료가 동시에 유효하다는 이유로 소속을 중복 생성하지 않는다.
3. 적용 관계를 결정할 근거가 없는 동급 중첩은 겹친 영역을 양쪽 형상에서 제외하고 자료 공백으로 남긴다. 조사한 동·서프로이센의 작은 중첩이 여기에 해당한다.
4. 명시적 대체와 부모 조정을 마친 뒤 남은 동급 중첩의 합집합을 원래 후보 형상들로부터 계산하고 한 번에 제외한다. 부모 형상이 다시 줄어들면 루트부터 아래로 하위 영토를 재조정한다. 입력 배열 순서로 소속이 바뀌지 않게 한다.
5. 기존 형상 연산의 정밀도·검증 기준을 재사용한다. 빈 결과와 실제 계산 실패를 구별한다. 계산 실패 또는 해결되지 않은 모델 충돌은 빌드를 실패시킨다.

대체 규칙은 entity 목록과 분리된 정책 자료에 둔다. 각 규칙에 대상·우선 영토·적용 기간·근거를 명시한다. 새 정책은 카탈로그 원본의 경계나 날짜를 덮어쓰지 않으며 파생 형상과 보고서만 만든다.

## 5. 빌드 산출물과 플랫폼 경계

```text
현대 스냅샷 + 역사 카탈로그/형상 + 명시적 영토 정책
  → 빌드 시 검증·구간 계산·형상 조정
  → 현재 프로젝트 형식의 기본 세계 + 자료 보고서 + 해시 manifest
  → 웹 초기화 / 앱 기존 import·모델 변환
  → 프로젝트의 timelineRecords와 불변 geometry archive
  → 기존 resolver → 해당 월의 view → 선택·공간 검색·렌더링
```

빌드 시 한 번 역사 자료를 표준 프로젝트 기록으로 변환한다. 실행 중 별도의 역사 세계 상태를 만들거나 날짜를 이동할 때마다 라이브러리 가져오기 명령을 실행하지 않는다.

### 공통 산출물

- 입력은 현대 스냅샷, 라이브러리 인덱스와 압축 형상, 기본 영토 분류, 명시적 중첩 정책이다. 필요한 파일의 누락·해시 불일치는 실패다.
- 출력은 웹의 현재 프로젝트 schema 10의 객체·timelineRecords·불변 geometry archive·provenance를 담은 기본 세계 자료다. 앱은 기존 import 경계에서 이를 현재 네이티브 모델로 변환하고 기존 네이티브 저장 형식으로 저장한다. 이번 연결만을 위한 프로젝트 저장 스키마 변경은 하지 않는다.
- 별도 manifest에 내부 산출물 버전, 입력 리비전과 해시, 현대 스냅샷 기준 월, 기본 세계와 보고서의 해시를 둔다. 보고서는 객체별 표시 가능 기간·제외 사유·형상 조정·미확정 중첩을 기록하며 제품 화면의 새 편집 상태가 되지 않는다.
- 날짜 이벤트 경계에서만 파생 기록을 생성한다. 모든 연월의 지도를 미리 생성하지 않는다. 동일 형상은 중복 저장하지 않는다. 객체·기록·형상 참조와 출력 순서는 결정적이다.
- 동일 입력을 재빌드하면 압축 전 canonical payload와 manifest의 내용 해시가 같다. 압축 파일을 미러링할 때에는 파일 해시도 일치해야 한다.
- 공통 자료는 웹 빌드에서 생성하고 앱 데이터 패키지에 같은 리비전으로 고정한다. 앱 실행 중 웹 배포 서버에 의존하지 않는다.

### 웹 연결

- `app-progressive-startup.js`와 `app-builtin-session.js`의 새 기본 세계 초기화 경로를 공통 산출물로 바꾼다. 새 세션·초기 시작·복원 없는 재진입 등 동일한 기본 세계 생성 경로를 함께 확인한다.
- `territorial-entity-store.js`가 전체 프로젝트 기록과 archive를 소유하며 기존 `restoreProject`와 커서 resolver를 사용한다.
- 기본 프로젝트의 최초 커서는 기존 새 프로젝트 설정을 따른다. 선택한 월에 자료가 없으면 빈 영토 상태를 허용하며 현대 세계로 바꾸지 않는다.
- 준비 전 현대 국가 미리보기가 필요한 기존 로딩 경로도 선택 월을 따라야 한다. 과거 월에서 현재 국가가 잠시 남거나 최종 결과 위에 겹치지 않도록 표시 소유권을 전환한다.

### 앱 연결

- `WorldDatasetLoader::canonical`과 `worldbootstrap.cpp`의 새 기본 세계 준비 경로에서 공통 산출물을 읽는다. 기존 import/model 변환 경계를 사용하며 라이브러리 전체를 별도의 편집 모델로 만들지 않는다.
- 기본 영토 분류, source ID → native 논리 ID 변환, 현대 기본 mesh의 `world-country-*` 형상 참조를 보존하는 명시적 어댑터를 둔다. 입력 geometry가 현대 canonical 형상과 실제로 같은지도 검증한다.
- 내부 ID·형상 참조 표기가 플랫폼별로 다르면 공통 source entity/version과 명시적 ID 대응표로 동등성을 비교한다. 대응표 없는 추론·문자열 별칭은 허용하지 않는다.
- `matchingBaseFrame` 등 정적 형상 기록을 전제한 호출부는 선택 월의 resolved view를 사용하도록 바꾼다. 전체 dated document를 정적 기록 조회 함수에 전달하지 않는다.
- 현대 기본 mesh는 선택 월에 활성인 동일 canonical 형상에만 사용한다. 역사 월의 비활성 영토나 변경된 형상을 현재 mesh로 덮어 표시하지 않는다. 기존 캐시·프레임 전환 최적화의 소유권은 유지한다.

수동 라이브러리 추가의 `instantiateLibraryEntity`/catalog adapter는 선택한 자료를 정적 사본으로 추가하는 기존 의미를 유지한다. 전체 세계 초기화와 수동 추가는 책임이 다르며 이번 작업 때문에 수동 추가 계약을 바꾸지 않는다.

## 6. 편집, 저장과 실패 처리

- 날짜 이동은 기존처럼 view만 변경한다. 콘텐츠 dirty, Undo/Redo, canonical 형상·관계 기록을 변경하지 않는다.
- 객체가 사라지거나 바뀌면 기존 선택·hit test·공간 인덱스·라벨·렌더 캐시를 canonical 커서/view 변경에 맞춰 갱신한다. 숨긴 영토를 클릭하거나 검색해 활성 영토처럼 편집할 수 없어야 한다.
- 해당 월의 편집은 기존 command/transaction과 월별 기록 분기 경계를 사용한다. 원본의 일자 기록, 인접 기간, 잠금, 원자성, Undo/Redo를 유지한다. 기본 자료라는 이유로 사용자 편집을 라이브러리 내용으로 다시 덮어쓰지 않는다.
- 저장·자동저장·내보내기는 화면에 표시된 월의 사본이 아니라 전체 기록과 archive를 보존한다. 다시 열면 저장한 자료를 사용한다. 배포 카탈로그가 변경되어도 저장된 프로젝트의 역사를 재생성하지 않는다.
- 복원된 프로젝트와 사용자가 만드는 빈 프로젝트는 기존 생성/복원 경로를 사용한다. 이번 기본 세계 변경을 위해 별도 호환 reader나 기존 프로젝트 마이그레이션을 추가하지 않는다.
- 기본 세계 자료의 로드·검증 실패는 기존 새 프로젝트 작업의 오류 경계로 전달한다. 부분 기록을 프로젝트에 확정하지 않는다. 현대 정적 세계로 조용히 대체하지 않으며 사용자가 재시도할 수 있도록 기존 실패 UI를 사용한다.

## 7. 구현 후 수용 기준

현재 조사한 자료 리비전에서 다음을 웹과 앱 각각 확인한다.

| 상황 | 기대 결과 |
| --- | --- |
| 새 기본 프로젝트에서 `2012-10` 선택 | 크림반도 확인점은 역사 우크라이나에 포함된다. 현대 러시아는 비활성이다. 우크라이나와 나고르노카라바흐 외의 현대 국가가 남지 않는다. |
| `2014-02` → `2014-03` → `2015-10` | 우크라이나는 2월에 표시되고 3월 월말에는 숨겨진다. 2015년을 현대 러시아/우크라이나 경계로 채우지 않는다. |
| 유고슬라비아 `1941-04` / `1945-10` / `1945-11` | 앞의 두 월은 자료 공백이며 1945년 11월에는 새 경계를 표시한다. |
| 나고르노카라바흐 `2020-10` → `2020-11` | 11월 9일/10일 경계 변경을 월말 해석으로 반영한다. 논리 ID는 유지한다. |
| 소련과 독립 우크라이나가 겹치는 1991년 | 명시적 대체 구역의 소속이 중복되지 않는다. 소련 하위 영토도 조정된 부모 범위 안에 있다. |
| `1991-12` | 12월 25일 종료한 SSR은 비활성이다. 소련의 원본 연도 정밀도 종료 의미는 유지한다. |
| 동·서프로이센 `1900-01` | 근거 없는 동급 중첩이 양쪽 소속으로 남지 않고 공백으로 보고된다. 북슐레스비히 하루 자료를 월말까지 늘리지 않는다. |
| 현대 스냅샷의 기준 월 | 기존 현대 세계의 분류·형상·이름·국기·색상과 일치한다. 남북한 등 동시 존재 객체를 합치지 않는다. |
| 현대 월 ↔ 과거 월 반복 이동 | 선택·라벨·공간 검색·렌더 결과가 해당 월과 일치한다. 현재 기본 mesh/preview의 잔상이 없다. dirty와 Undo 항목은 늘지 않는다. |
| 역사 월의 편집 후 Undo/Redo와 저장·재열기 | 변경한 기록의 기간과 나머지 기간을 보존하며 전체 역사가 복원된다. 라이브러리 재조회로 편집을 되돌리지 않는다. |
| 앱 오프라인 / 웹 데이터 로드 실패 | 앱은 고정한 자료로 동작한다. 웹 실패는 새 프로젝트 확정을 막고 오류를 표시한다. |

필요한 검증 범위는 빌더의 기간·중첩·결정성 검사, 공통 fixture에 대한 JS/C++ resolver 및 저장 동등성, 기본 세계 초기화와 날짜 이동의 집중 브라우저/Qt 검사다. App의 실제 현재 mesh 전환과 Web의 실제 기본 세계 생성 경로를 확인한다. 형상 포함·소속·기록·dirty·Undo 결과를 검사하며 UI 요소의 존재만으로 통과시키지 않는다.

문서만 작성한 단계에서는 제품 테스트를 실행하지 않는다. 구현 단계의 집중 검사가 통과하면 관련 실패나 새로운 영향이 없는 한 전체 테스트로 범위를 늘리지 않는다.

## 8. 작업 위치와 다음 단계

웹은 `D:/dev/worktrees/web/objects`, 앱은 `D:/dev/worktrees/app/objects`의 상설 `work/objects`를 사용한다. 두 저장소에 이 문서를 동일하게 보관한다. 기존 작업 디렉터리와 무관한 변경을 보존한다.

읽은 최신 `origin/main` 기준은 웹 `b530be173f6033f6eb3e3e173258ed53ff92b706`, 앱 `ff03b4383f894fe2e187b58c9c4c52be0d9510bf`다. 구현 계획 확정 후 실제 구현 전에 원격 상태를 다시 확인하고 최신 main을 각각 work/objects로 병합한다. 기존 작업 브랜치의 경계 프레임 전환 수정도 보존한다. 현재 코드와 테스트가 이전 문서보다 우선한다.

문서 승인 후 구현 계획에서 산출물 생성·웹 초기화·앱 변환·집중 검증의 파일 및 실행 순서를 확정한다. main 반영이나 배포는 별도 명시적 지시가 있어야 한다. 로컬 검증·커밋·푸시와 실제 배포 반영은 각각 증거를 확인한다.
